# “内容安全校验暂不可用”排查

原来的提示会将多种失败归并为同一句话，仅凭压缩后的 appservice 调用栈无法定位。更新前端并重新编译预览后，开发控制台会新增一行：

```text
[content-security] {"stage":"cloud_allocate","reason":"service_rejected","platformCode":-502005}
```

这只是格式示例，不代表已经确认当前手机上的根因。日志只保留固定阶段、原因、数字错误码和受限的随机请求号，不包含原始异常文本、图片路径、身份、URL、登录 code 或密钥。用户界面仍使用统一失败提示；违规时仍只提示“所发布内容含违规信息”，不会跳过检测。

## 先确认所选后端

查看 `miniprogram/config/index.js` 的 `contentSecurity.backend`。目前默认是 `cloud`，环境为 `photo-d0gn3yvetb21c4a41`，函数为 `contentSecurity`。选择 `cloud` 时排查微信云开发，不应根据 ECS 状态推断小程序失败原因；选择 `http` 时才排查自有服务器。两者都不会在错误时自动切换或免检。

| stage / reason | 检查方向 |
| --- | --- |
| `configuration / invalid_configuration` | 检查实际编译使用的配置，环境 ID、函数名或 HTTPS 地址是否完整 |
| `cloud_init / unsupported_api` | 当前微信和基础库是否支持云开发 API |
| `cloud_allocate` | 云函数是否部署在同一环境，是否绑定当前 AppID；若返回数字云错误码，按该码查同次云函数日志 |
| `cloud_configuration / callback_config_missing` | 云函数环境变量中回调 Token 或 EncodingAESKey 未设置；它们不等于小程序上传私钥 |
| `cloud_configuration / callback_config_invalid` | 云函数中的 EncodingAESKey 格式不是要求的 43 字符；不要把值发到聊天中 |
| `cloud_identity / appid_mismatch` | 实际小程序 AppID 与云函数预期 AppID 不一致 |
| `cloud_allocate` 且 `platformCode=-502005` | 检查云数据库集合是否已创建，特别是首先使用的限流集合 |
| `cloud_upload / permission_denied` | 检查云存储所属环境、访问权限；不能以公开读写解决权限问题 |
| `session / domain_not_allowed` | 自有后端域名未在微信 request 合法域名中配置 |
| `session / tls_failed` | 自有后端 HTTPS 证书与证书链是否有效 |
| `session / http_error` | 查看 HTTP 状态；404 常见于反向代理路径错误，503 需检查服务器登录/数据库/微信错误日志 |
| `allocate`、`upload`、`submit`、`status` | 分别为任务分配、图片上传、检测提交、结果查询；结合 HTTP 状态或随机 requestId 查询后端日志 |
| `file_binding / digest_mismatch` 或 `file_changed` | 服务端收到的文件与本地图片不一致，不能复用检测结果 |
| `timeout` 或 `network_failed` | 结合对应阶段检查网络和服务耗时，不把超时当成安全通过 |

云函数若仍运行旧版本，只能返回统一的 `service_rejected`。需要在对应云开发环境部署更新后的 `backend/cloudfunctions/contentSecurity`，才能获得配置缺失等服务端诊断。**仅更新 Git 仓库不会自动更新手机代码或云函数。**

## 在小程序客户端核对云函数调用

在已初始化云开发的微信开发者工具调试控制台运行以下语句，可确认真实客户端是否能调用函数。该操作只分配一个任务，不上传照片，输出也不包含任务归属或上传路径：

```js
wx.cloud.callFunction({
  name: 'contentSecurity',
  config: { env: 'photo-d0gn3yvetb21c4a41' },
  data: { action: 'allocate' }
}).then(({ result }) => {
  console.log({ ok: result && result.ok, code: result && result.code,
    diagnostic: result && result.diagnostic })
}).catch(error => console.log({ errCode: error.errCode }))
```

将 `[content-security]` 那一行或上述有限输出用于定位即可，不需要提供上传私钥、Token、AESKey、OpenID、完整云函数事件或图片。

自有 HTTP 后端新增 `X-Request-ID` 响应头，并在失败响应与 HTTP 日志中记录同一个随机请求号；需要更新后端后才生效。该请求号不表示检测通过，也不包含用户身份。
