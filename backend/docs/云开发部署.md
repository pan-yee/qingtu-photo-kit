# 微信图片内容安全部署与联调

> 前端默认选择微信云开发（`backend: 'cloud'`），目标环境为 `photo-d0gn3yvetb21c4a41`、函数名为 `contentSecurity`。本页说明云模式部署与验收；默认参数不代表云端资源和权限已就绪。

> 自有部署仍保留，可将前端参数改为 `backend: 'http'`。自建服务支持 `MODERATION_MODE=sync`，不依赖异步回调；其部署步骤见 [后端部署说明](../README.md)。两套后端分别配置，不会互相自动回退。


本次审核要求证件照场景接入内容安全 API。云函数默认使用微信异步多媒体检测 `security.mediaCheckAsync`；通过云函数环境变量 `CONTENT_SECURITY_AUDIT_MODE=sync` 可选择同步图片检测 `security.imgSecCheck`。不能用文本接口检测固定文案代替图片检测。

云函数运行时应使用 Node.js 20.19 或更高版本；需要分别核对数据库、权限与临时文件清理是否已配置。同步模式不要求回调变量，异步模式还需要可信回调。云端实际可用性须以真实调用测试为准。

## 1. 准备微信云开发环境

使用此 AppID 绑定的云开发环境。云函数代码由后端项目的 `cloudfunctions/` 管理，前端不声明跨项目的 `cloudfunctionRoot`；需要在后端项目中单独配置云函数部署工具。小程序端仍无第三方 npm 运行时依赖；云函数使用固定的 `wx-server-sdk@4.0.2` 和锁文件。

在 `backend` 目录安装云函数依赖，或在微信开发者工具上传时选择“云端安装依赖”：

```sh
npm ci --prefix cloudfunctions/contentSecurity
```

将 `cloudfunctions/contentSecurity` 部署为 Node.js 20.19 或更高的事件云函数，函数名保持 `contentSecurity`。选择足够覆盖图片下载与缩放的内存和超时，例如 256 MB、30 秒。`config.json` 声明 `security.imgSecCheck` 和 `security.mediaCheckAsync` 云调用权限；在当前小程序后台确认所选 API 的可用性及授权。SDK 云调用使用平台身份，不需要在前端放置 AppSecret 或 access_token。同步模式生成不裁剪、最大 750×1334 且小于 1 MiB 的 JPEG 检测副本，限制像素及并发；实际审核结果仍绑定上传原图的 SHA-1。

## 2. 数据库与云存储

建立三个集合：

- `content_security_jobs`：任务归属、文件摘要、微信 traceId、状态、过期时间。
- `content_security_receipts`：暂存可能早于 API 应答落库的已验签回调。
- `content_security_limits`：服务端每用户每分钟最多 20 个任务的事务计数。

三个集合的客户端读写权限全部设为禁止，规则内容见云函数目录 `database.rules.json`。只有云函数管理身份访问。为 `content_security_jobs.traceId` 建立查询索引。任务和收件箱的 `expiresAt` 是毫秒时间戳；后台定期清理过期元数据，不要把数字字段误设为要求 Date 类型的 TTL 索引。

云存储使用“仅创建者及管理员可读写”权限，不能设为公开读写。客户端只能操作自己上传的 `moderation-inbox/` 文件。服务端将图片复制到随机的 `moderation-private/` 对象后送检，客户端不能覆盖服务端副本。微信检测使用服务端生成的短期 HTTPS 签名链接，链接不返回前端。

检测完成、检测出错或状态查询发现任务过期时，服务端删除临时对象；客户端也在结束时删除自己的上传对象。**还必须为两个临时前缀配置云存储生命周期清理（建议 1 天）**，处理客户端中断、回调丢失或删除失败造成的残留。图片只用于内容安全，不用于训练、公开展示或其他业务保存。按实际部署的清理周期填写隐私说明，不要承诺未实施的保留时限。

## 3. 配置可信微信回调（仅异步模式）

默认异步模式需要本节配置；仅显式设置 `CONTENT_SECURITY_AUDIT_MODE=sync` 时不需要回调变量。

为事件云函数配置 HTTPS 访问服务，使用支持 `httpMethod / queryStringParameters / body` 事件及 `statusCode / headers / body` 集成响应的模式。不要使用需要另行启动 HTTP Server 的 Web 函数模式。URL 必须可被微信服务器访问。

在**云函数环境变量**中配置：

| 名称 | 内容 |
| --- | --- |
| `CONTENT_SECURITY_APP_ID` | 当前小程序 AppID；仓库默认 `wx2b68d0818781b66d` |
| `CONTENT_SECURITY_CALLBACK_TOKEN` | 消息推送配置使用的 Token，安全生成并仅保存在服务端 |
| `CONTENT_SECURITY_CALLBACK_AES_KEY` | 消息推送配置使用的 43 字符 EncodingAESKey |

在微信小程序后台的消息推送设置填写同一个 HTTPS URL、Token 和 EncodingAESKey，启用加密安全模式。URL 验证的 GET 请求支持普通签名及加密 echostr；POST 只接受已验签、已解密、接收 AppID 匹配的 `wxa_media_check` 消息，支持 JSON 和 XML 包装。不要把裸的 `status: pass`、客户端传入的事件或未经验证的消息写入任务结果。

先确保后台 URL 验证成功，再发起真实图片检查。若当前后台的消息推送入口或事件格式与此模式不同，应适配并实测回调，不能关闭签名校验，也不能将任务受理当成通过。消息推送配置可能影响现有服务：若原来已有接收端，应在现有可信服务中转发这一事件，保留其他事件处理，不能直接覆盖原配置。

## 4. 启用客户端与隐私说明

前端 `miniprogram/config/index.js` 默认已设置 `{ backend: 'cloud', envId: 'photo-d0gn3yvetb21c4a41', functionName: 'contentSecurity' }`，并同时保留自建 `apiBaseUrl`。修改环境参数或切换后端后重新编译。环境 ID 不是密钥，不需要另加“关闭校验”的开关。环境或服务不可用时不放行，也不在开发版/体验版绕过。

小程序后台隐私保护指引必须声明：选图、相册写入、为内容安全检测临时向微信云开发上传图片、交由微信内容安全服务检测，以及真实的存储地点、运营者和保留/清理策略。前端已更新“不上传”的旧说明，并在第一次实际检测前再次征求上传同意；不同意时不上传，仍可浏览介绍。

原始素材及加工结果都需要检测：选图入口先检查素材；画布导出和压缩结果通过后才进入预览；大图预览与相册保存再次核验文件摘要和短期结果。拼接、擦除、九宫格与证件照使用同一链路。不存在将激励广告成功视为安全通过的分支。

## 5. 真机联调与审核证据

使用自己的合规测试图，在微信开发者工具及真机确认：

1. 默认异步模式真实调用 `mediaCheckAsync`，返回 traceId 后必须等待可信加密回调 `pass`；同步模式的 `imgSecCheck` 必须由微信明确返回成功后才能显示结果和保存。
2. 后台按平台允许的方式提供违规测试图/测试事件时，实际拒绝结果会拦截所有预览和保存入口，只提示 **“所发布内容含违规信息”**。不要在用户界面输出违规分类、命中细节或内部错误码。
3. 停用回调、断网、API 权限不足、超时、`review`、未知状态和未配置环境时，都不能保存。不要仅测试一个伪造的前端返回值。
4. 修改图片、换底色、换尺寸及生成新拼接/九宫格后，按实际字节内容检查，旧结果不能无条件放行新文件。九宫格批量保存会先检查全部 9 张，避免其中一张失败时先保存部分图片。
5. 确认拒绝上传时没有云端文件，检测完成后临时对象被删除；异常对象的生命周期清理已启用。

保留当前版本的接口调用时间、traceId、可信回调状态及操作路径作为审核证据，日志不要包含用户图片、签名临时 URL、Token、AESKey 或完整用户身份。完成真实联调后再使用审核说明中的回复模板；本地测试通过不能证明真实微信 API 或审核已经通过。
