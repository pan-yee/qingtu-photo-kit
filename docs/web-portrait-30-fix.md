# 证件照错误输出修复与同批复测（2026-11-11）

针对 [30 张公开照片验证](web-portrait-30-validation.md) 中的错误输出，移除 Haar 人脸检测，换成带固定哈希校验的 OpenCV YuNet 2023mar 模型（232589 字节，MIT 许可，随镜像分发）。MODNet 权重、ECS CPU、700 MiB worker 内存限额和微信云环境安全检测保持原配置，不新增 GPU 或收费抠图 API。

## 改动

- 检查主要人脸数量、五点几何姿态、最小脸部尺寸、头顶完整性和脸部 alpha 覆盖。条件不合适时返回受限的素材错误码，在模型推理前尽可能停止处理；不补画或强行保留缺失的头部。
- 客户端只接收协议 2 / YuNet 的单人脸结果，不再把旧版空人脸元数据或检测失败当作可用居中构图。
- 最终裁切必须完整包含人脸，且下沿不越出源图，避免横幅照片身体下方出现空白底色条。
- 422 素材拒绝码在 worker、Node API 和小程序之间明确传递，提示换图；未知内部错误不会透传。

## 同一批 30 张结果

- 10 张生成结果，20 张拒绝：15 张未检出可用人脸、4 张头部不完整、1 张明显侧向姿态。拒绝不等于修复或补全原图，也不能用这组包含大量背影、遮挡的样本计算证件照通过率。
- 原先严重裁错主体的 `310`、`344`、`396` 不再生成衣服或头发局部；遮挡样本 `293` 不再生成丢失头部的结果。
- `103` 不再把衣摆当成第二个人脸，能够生成主要人脸构图。正常样本 `017`、`138`、`189`、`241`、`482` 均保留生成路径。
- 发丝与浅色衣物仍不能保证全自动完美，本批 `275` 仍有浅色背景残留，需手动涂抹；五点几何检查也不是闭眼、表情或机构受理标准认证。

完整逐张结果见 [复测 JSON](validation/web-portrait-30-fixed-report.json)。这 30 张曾用于诊断和改进实现，因此属于同批回归，不是独立留出的泛化测试集。复测调用真实 worker 的素材校验、模型推理及小程序实际构图/边缘处理代码，没有用伪造成功响应或删除失败样本来提高结果。不同接受样本集合之间的平均误差不作质量排名。

## 验证与部署

- 前端检查与 170 项测试、后端检查与 31 项测试、7 项 Python worker 测试通过。
- 已部署 ECS，旧镜像和源码备份保留在 `/opt/qingtu-photo-kit/backups/yunet-20261111/` 与 `before-yunet-20261111` 镜像标签。
- ECS 本机 API 实测：正常 NASA 公共测试人像返回协议 2 / YuNet / 单人脸；空白素材返回 422；未登录请求拒绝。正常请求约 699 ms，含本机 API 与模型，不代表手机端延迟。测试使用服务器签发的短期隔离 JWT，不能替代手机微信登录验收。
- worker 以 UID 65534、只读根文件系统运行，Docker 内存硬限额 734003200 字节；该次请求后内存约 333.8 MiB，未做持续并发压测。
- 外部域名复测仍为 HTTP 403 / `Non-compliance ICP Filing`，手机验收仍受备案阻断影响。功能代码修复与解除域名阻断是两项不同工作。

复现本地同批测试：在安装 `backend/matting/requirements.txt` 的独立环境设置 `MODNET_MODEL_PATH`，执行 `scripts/retest-portrait-web30.py --baseline /path/to/original-review --output /path/to/fixed-review`；再运行 `scripts/build-portrait-fixed-review.py` 生成逐张对比 HTML。发布后必须重新编译小程序以使用协议 2。
